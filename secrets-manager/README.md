# Secrets Manager for Claude Code (Infisical)

> **Value:** High &nbsp;|&nbsp; **Implementability:** Moderate

## What this is
Wire an open-source secrets vault (e.g. Infisical) into your Claude Code workflow so API keys/passwords are injected from the vault instead of being pasted into chat.

## Why it's worth building
The underlying claim is TRUE and important: Claude Code persists session transcripts as JSONL on disk, so anything you paste (keys, tokens) lands in plaintext. A vault keeps raw secrets out of the context window and off disk. Real security win.

## What to build (the gist)
- Audit what you've pasted historically — assume those secrets are on disk and rotate them.
- Inject secrets at run time from the vault; reference by name, never by value, in prompts.
- Add the vault's CLI as an allowlisted command so Claude can fetch without seeing raw values.
- Good companion to a .gitignore/secret-scan pass on this repo.

## First steps
1. Skim the source posts' extracts in `exports/items/` for the exact text/claims.
2. Stand up the smallest useful version first (one file / one skill / one template).
3. Wire it into your existing Claude Code setup; iterate.

## What's here
- **`SETUP.md`** — concrete, vendor-light guide: the real risk (transcripts persisted as plaintext JSONL), a lighter env-vars + direnv path, the stronger Infisical-vault path, how to allowlist the vault CLI so Claude fetches without seeing values, and a "rotate anything already pasted" checklist.
- **`scripts/secret_env.py`** — dependency-free helper (stdlib only). Reads secret NAMES from a manifest, resolves each from the environment or a vault CLI, and prints a **redacted** summary so prompts reference `${NAME}`, never raw values.
- **`scripts/secrets.example.txt`** — the manifest of secret NAMES (commit this; it holds no values, and a guard rejects value-looking lines).
- **`test_secret_env.py`** — TDD tests (13, all passing).

## Usage
```bash
# 1. List your secret NAMES in scripts/secrets.example.txt (NAMES, not values).

# 2. (Optional) point the helper at a vault CLI:
export SECRET_ENV_VAULT_CMD="infisical secrets get {name} --plain --env=dev"

# 3. Redacted status — safe to show Claude / paste anywhere:
python scripts/secret_env.py

# 4. In YOUR own terminal, export real values for eval (NOT the chat window):
eval "$(python scripts/secret_env.py --export)"

# Run the tests:
.venv\Scripts\python.exe -m pytest projects\claude-code-secrets-manager
```
See **`SETUP.md`** for the full vault wiring and rotation checklist.

## Effort
Install the vault, move secrets in, expose them via env/CLI to your tools; some setup but well-trodden.
